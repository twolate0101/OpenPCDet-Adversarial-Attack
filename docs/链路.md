自动驾驶 3D 点云对抗攻击项目：架构解析与实施链路说明
在本项目中，为了在现代工业级自动驾驶框架中实现高阶的安全攻防测试，我们采用了**“理论解耦与跨框架移植”**的软件工程策略。本节将详细说明项目中三个核心要素的定位，以及具体的复现落地链路。

一、 核心要素定位与作用剖析 (The Triad Architecture)
本项目涉及的三大核心要素并非平行关系，而是分别扮演了**“理论祖师”、“工程图纸”与“物理引擎”**的角色。

1. CVPR 2019 经典论文：《Generating 3D Adversarial Point Clouds》
角色定位：理论奠基者（The Theory Foundation）

项目作用：它是整个项目的“数学灵魂”。该论文首次在学术界证明了 3D 点云网络的脆弱性，并给出了三种最基础的攻击数学模型：点云坐标微扰（Perturbation）、点插入（Generation）和关键点删除（Dropping）。

局限性：原论文针对的是简单的“3D 形状分类”任务（孤立的杯子/椅子），其祖传代码无法直接运行在复杂的自动驾驶街景数据上。我们在项目中只取其算法公式与核心思想，不使用其原始代码库。

2. OpenPCDet 开源框架
角色定位：底层宿主引擎（The Host Engine）

项目作用：它是我们项目的“物理战场”。这是目前工业界最主流的纯 PyTorch 3D 目标检测代码库（包含 PointPillars 等先进模型）。它负责繁重的基础工作：读取上百 GB 的 KITTI 数据、进行复杂的 3D 稀疏卷积运算，并输出最终的车辆检测框。

使用方式：我们全盘接收并搭建该框架，将其作为攻击的目标（靶机）和评估的基准（Baseline）。

3. Robust3DOD (~2023年相关论文及仓库)
角色定位：工程适配图纸（The Blueprint / Reference）

项目作用：它是连接“19年古老理论”与“现代 OpenPCDet 框架”的桥梁。该仓库作者成功将 19 年的攻击数学模型，改写成了能适配 OpenPCDet 数据结构的格式。

核心排雷策略（重要）：为了避免深陷依赖地狱（Dependency Hell）和底层 C++ 算子版本冲突，我们绝对不克隆（git clone）、不运行该仓库的完整代码。我们将其视为一个**“算法参考字典”**，从中提取纯粹的张量修改（Tensor Manipulation）代码片段。

二、 核心复现链路与操作指南 (Implementation Pipeline)
基于上述架构定位，本项目的实施链路摒弃了传统的“拉取仓库直接跑”，而是采用了更为高级的**“数据流拦截与代码手术（Data Interception & Code Injection）”**模式。

具体复现步骤如下：

阶段一：搭建宿主环境与确立基准（已完成）
框架部署：在 vGPU-48GB 云服务器上，独立克隆并从零编译最新的 OpenPCDet 框架，配置 PyTorch 与 spconv 底层算子。

数据挂载：清洗并挂载 KITTI 3D 数据集。

基线验证：运行官方 PointPillars 预训练权重。在 tools/demo.py 中重构可视化代码，验证框架能在未受攻击的原始数据上，准确输出车辆的 3D 检测框（BEV 鸟瞰图形式）。这确立了我们的 Golden Baseline。

阶段二：实施“拦截器”攻击策略（当前进行中）
这一阶段的核心是**“不动模型，只动数据”**。我们将参考 Robust3DOD 的核心逻辑，手动修改 OpenPCDet 的推理脚本进行攻击。

确立拦截点：

打开 OpenPCDet 的 tools/demo.py 脚本。

追踪数据流，定位到点云被加载进显存后、喂给模型前向传播函数前的那一刻（即变量 data_dict['points']）。

提取与改写攻击逻辑：

翻阅 Robust3DOD 的 GitHub 源码，找到实现特定攻击（如：关键点 Dropping 或 PGD Perturbation）的那几十行核心 PyTorch 张量操作代码。

剔除其冗余的框架封装，提取纯净的数学计算逻辑。

代码注入（代码手术）：

将提取出的攻击函数，作为“补丁”直接粘贴进 demo.py 中。

在模型执行 pred_dicts, _ = model.forward(data_dict) 之前，调用该攻击函数，强行修改 data_dict['points'] 的坐标或数量，生成“对抗性数据字典”。

阶段三：攻击效果评估
将被篡改过的“毒化点云”喂给毫不知情的 PointPillars 模型。

再次调用我们魔改的 BEV 渲染器，生成 result_bev_attacked.png。

对比攻击前后的图片和检测框置信度，量化评估模型的漏检率（False Negative）与误检率（False Positive），最终形成系统的安全性评估报告。
