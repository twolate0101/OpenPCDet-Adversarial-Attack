## 第三章：攻击算法实现指南

### 3.1 接口规范（必须遵守）

所有攻击器必须遵守 `tools/attackers/base.py` 定义的接口：

```python
# tools/attackers/base.py — 基类定义
class BaseAttacker:
    def __init__(self, severity=1.0, **kwargs):
        self.severity = severity

    def forward(self, data_dict):
        """
        核心拦截接口。必须重写。

        参数:
            data_dict: OpenPCDet 字典
                - data_dict['points']: 点云数据
                  注入点A (demo.py): GPU tensor (N,4) [x,y,z,intensity]
                  注入点B (test.py):  GPU tensor (N,5) [batch_idx,x,y,z,intensity]
        返回:
            修改后的 data_dict（保持字段结构不变）
        """
        raise NotImplementedError
```

**核心约束**：
1. 继承 `BaseAttacker`，实现 `forward(self, data_dict)` 方法
2. 只能使用 PyTorch 原生算子操作 `data_dict['points']`
3. 返回的 `data_dict` 必须保持原有字段结构，`points` 的 shape 只能行数变化、列数不变
4. 完成后在 `tools/attackers/__init__.py` 的 `get_attacker()` 中注册

### 3.2 梯度约束分析（必读：理解攻击策略的前提）

**核心结论：OpenPCDet/PointPillars 不支持端到端梯度反向传播。** CVPR 2019 论文中的白盒攻击方法（PGD、C&W 等）和 Robust3DOD 的梯度攻击方法，均无法在当前框架下直接使用。

OpenPCDet 的推理链路中有 **5 个梯度断裂点**：

| 序号 | 断裂点 | 文件位置 | 原因 |
|------|--------|---------|------|
| 1 | 体素化 | `pcdet/datasets/processor/data_processor.py` | 返回 NumPy 数组，无梯度追踪 |
| 2 | spconv 稀疏张量索引 | `pcdet/models/backbones_3d/spconv_backbone.py` | 索引为整数坐标，不可微 |
| 3 | PillarVFE max pooling | `pcdet/models/backbones_3d/vfe/pillar_vfe.py` | 仅最大点获梯度，其余点梯度为零 |
| 4 | BEV Pooling CUDA 算子 | `pcdet/ops/bev_pool/bev_pool.py` | `ctx.mark_non_differentiable(geom_feats)` 显式标记不可微 |
| 5 | NMS 后处理 | `pcdet/models/model_utils/model_nms_utils.py` | 离散索引选择，不可微 |

**这意味着**：即使在输入点云上设置 `requires_grad_(True)`，梯度也无法从模型输出回传到输入点云。PGD、FGSM、C&W 等依赖梯度的白盒攻击在当前架构下不可行。

**我们的应对策略**：采用三层攻击体系——

| 层次 | 攻击类型 | 是否需要梯度 | 优先级 |
|------|---------|-------------|--------|
| 第一层 | 梯度无关攻击（黑盒） | 不需要 | **核心实现** |
| 第二层 | 有限梯度攻击（需修改模型） | 部分需要 | 仅作参考提及 |
| 第三层 | 迁移攻击（代理模型） | 在代理上需要 | 高档加分项 |

### 3.3 梯度无关攻击（主攻方向，立即可用）

以下攻击方法无需任何模型修改，可立即在当前框架下实现。

#### 3.3.1 随机坐标微扰（NoiseAttacker，已实现）

当前实现位于 `tools/attackers/__init__.py` L13-28，给所有点的 x,y,z 加高斯噪声，标准差由 severity 控制。

**理论依据**：CVPR 2019 论文中的 Perturbation 攻击的简化版本。原论文使用 PGD/C&W 优化扰动方向，我们用随机噪声替代，攻击效率较低但实现简单、无需梯度。

**使用命令**：
```bash

  --ckpt ../ckpts/pointpillar_7728.pth \
  --data_path ../data/kitti/testing/velodyne/000008.bin \
  --attack noise --severity 0.5
```

#### 3.3.2 随机点删除（DropAttacker，待实现）

随机丢弃一定比例的点，模拟传感器遮挡或信号丢失。

**理论依据**：CVPR 2019 论文中 Dropping 攻击的简化版本。原论文通过 Saliency Map 选择关键点删除，我们用随机选择替代。

```python
# tools/attackers/drop.py
import torch
from .base import BaseAttacker

class DropAttacker(BaseAttacker):
    """随机点删除攻击：按 severity 比例随机丢弃点云中的点"""
    def forward(self, data_dict):
        points = data_dict['points']
        batch_idx = points[:, 0].long() if points.shape[1] > 4 else None

        if batch_idx is not None:
            # batch 场景：按样本独立删除
            result_parts = []
            for bid in batch_idx.unique():
                mask = (batch_idx == bid)
                sample_pts = points[mask]
                keep_count = max(1, int(sample_pts.shape[0] * (1 - self.severity)))
                keep_idx = torch.randperm(sample_pts.shape[0], device=sample_pts.device)[:keep_count]
                result_parts.append(sample_pts[keep_idx])
            data_dict['points'] = torch.cat(result_parts, dim=0)
        else:
            # 单帧场景
            keep_count = max(1, int(points.shape[0] * (1 - self.severity)))
            keep_idx = torch.randperm(points.shape[0], device=points.device)[:keep_count]
            data_dict['points'] = points[keep_idx]

        return data_dict
```

severity 映射：severity=0.1 → 删10%，severity=0.5 → 删50%，severity=1.0 → 删90%

#### 3.3.3 几何感知删除（GeoDropAttacker，待实现，推荐）

比随机删除更智能：优先删除距离点云质心近的点（靠近目标的点对检测贡献更大）。

**理论依据**：3D 目标检测依赖目标区域的点云密度。删除靠近质心的点，等价于削弱目标的特征表达，比随机删除更有效。

```python
# tools/attackers/geo_drop.py
import torch
from .base import BaseAttacker

class GeoDropAttacker(BaseAttacker):
    """几何感知删除：优先删除距质心近的点（目标区域点），无需梯度"""
    def forward(self, data_dict):
        points = data_dict['points']
        batch_idx = points[:, 0].long() if points.shape[1] > 4 else None

        if batch_idx is not None:
            result_parts = []
            for bid in batch_idx.unique():
                mask = (batch_idx == bid)
                sample_pts = points[mask]
                result_parts.append(self._drop_by_distance(sample_pts))
            data_dict['points'] = torch.cat(result_parts, dim=0)
        else:
            data_dict['points'] = self._drop_by_distance(points)
        return data_dict

    def _drop_by_distance(self, points):
        num_pts = points.shape[0]
        drop_count = int(num_pts * self.severity)
        keep_count = num_pts - drop_count

        # 计算每个点到质心的距离
        centroid = points[:, :3].mean(dim=0)
        distances = torch.norm(points[:, :3] - centroid, dim=1)

        # 保留距离远的点（删除距离近的=目标区域点）
        _, keep_indices = distances.topk(keep_count, largest=True)
        return points[keep_indices]
```

#### 3.3.4 点插入攻击（AttachAttacker，已实现，建议优化为密度感知插入）

当前 `tools/attackers/attach.py` 的实现是随机采样+加噪插入。局限性：插入位置随机，大概率落入空旷区域，影响甚微。

**优化方向：密度感知插入**。在已有點云密集区域（即目标区域）附近插入点，制造假阳性检测或干扰已有检测：

```python
# 优化版：密度感知插入（伪代码示意）
class AdvAttachAttacker(BaseAttacker):
    def forward(self, data_dict):
        points = data_dict['points']
        num_pts = points.shape[0]
        ratio = 0.02 + self.severity * 0.18
        insert_count = min(int(num_pts * ratio), int(num_pts * 0.5))

        # ★ 改进：随机选种子点作为锚点（大概率落在目标区域）
        anchor_idx = torch.randint(0, num_pts, (insert_count,), device=points.device)
        anchors = points[anchor_idx]

        # 在锚点附近生成新点（较小噪声 → 形成密集簇）
        noise = torch.randn(insert_count, points.shape[1], device=points.device) * 0.025
        new_points = anchors + noise

        # 边界裁剪
        new_points[:, 1] = torch.clamp(new_points[:, 1], -75.2, 75.2)
        new_points[:, 2] = torch.clamp(new_points[:, 2], -40.0, 40.0)
        new_points[:, 3] = torch.clamp(new_points[:, 3], -3.0, 1.0)

        data_dict['points'] = torch.cat([points, new_points], dim=0)
        return data_dict
```

### 3.4 有限梯度攻击（可选探索方向，仅作参考提及）

CVPR 2019 论文和 Robust3DOD 中的核心攻击方法（PGD 微扰、Saliency-based 删除）均依赖梯度。Robust3DOD 的做法是删除 `dynamic_mean_vfe.py` 中的 `@torch.no_grad()` 装饰器来启用 VFE 层的梯度计算。

**但本项目的原则是"不动模型"**，且即使启用 VFE 梯度，梯度仍无法通过体素化和 spconv 回传到输入点云。因此，有限梯度攻击在当前架构下的可行性有限，仅作为可选探索方向提及，不提供具体实现代码。

**如果团队后续决定尝试**，可参考 Robust3DOD 项目（https://github.com/Eaphan/Robust3DOD）的 `attack.py`、`remove.py`、`attach.py` 实现。

### 3.5 迁移攻击（高档加分项）

**核心思路**：用一个全可微的代理模型（如 PointNet/PointNet++）生成对抗样本，然后测试这些对抗样本能否迁移到 PointPillars 上造成性能下降。

**为什么迁移攻击可行**：
- PointNet/PointNet++ 是全可微网络，可自由使用 PGD/FGSM 等白盒攻击
- 学术研究表明，3D 点云对抗样本具有一定的跨模型迁移性
- 即使迁移效果不佳，"迁移性分析"本身也是有价值的实验发现

**实施方案**：

1. **搭建代理模型**：
   - 使用 PyTorch 实现简单的 PointNet 分类器
   - 在 KITTI 点云数据上训练（或用预训练权重）
   - 任务：将点云分为"含车辆"和"不含车辆"两类

2. **在代理模型上生成对抗样本**：
   - 使用 PGD 攻击在 PointNet 上优化点云坐标
   - 保存扰动后的点云数据

3. **测试迁移效果**：
   - 将扰动后的点云输入 PointPillars
   - 对比 PointPillars 在原始点云 vs 扰动点云上的 mAP
   - 分析迁移攻击的成功率和局限性

**实验预期**：
- 迁移攻击的效果通常弱于白盒攻击（这是正常的）
- 关键不在于攻击效果多强，而在于系统化分析"3D对抗样本是否具有跨架构迁移性"
- 这本身就是一个有价值的研究发现

            'Car_3d_Moderate': match.group(2),

# 写出 CSV

## 第六章：高档评分改进方向

### 6.1 方向一：从随机攻击升级为几何感知攻击

当前基础攻击（NoiseAttacker、随机DropAttacker）都是无差别的随机策略。升级为几何感知攻击是最直接的改进方向：

**6.1.1 几何感知删除（GeoDropAttacker）**

已在 3.3.3 节给出实现代码。核心改进：优先删除距质心近的点（目标区域），比随机删除更有效。

**6.1.2 密度感知插入（AdvAttachAttacker）**

已在 3.3.4 节给出优化方案。核心改进：在已有點云密集区域附近插入点，比随机位置插入更可能干扰检测。

**6.1.3 物理合理性约束**

CVPR 2019 论文中的攻击是"数字域攻击"——可以任意修改点云坐标，但在物理世界中不可实现。添加物理约束使攻击更具现实意义：

- **LiDAR 射线方向约束**：扰动只能沿射线径向方向，不能横向偏移
- **可见性约束**：插入的点必须位于传感器视线上，不能在遮挡物后面
- **反射率约束**：新增点的 intensity 值必须符合物理材料的反射率范围

### 6.2 方向二：轻量级鲁棒增强策略

这是大作业要求中**明确鼓励**的方向。核心思路：在体素化之前增加一道"清洗"预处理，过滤掉攻击注入的异常点。

**方案1：统计离群点移除（Statistical Outlier Removal, SOR）**

最推荐的轻量级防御方案：

```python
# 伪代码：SOR 去噪防御
def sor_defense(points, k=10, threshold=2.0):
    """
    对每个点找 k 个最近邻，计算平均距离。
    如果平均距离超过全局均值 + threshold * 标准差，则视为离群点删除。
    """
    dist_matrix = torch.cdist(points[:, :3], points[:, :3])  # (N, N)
    knn_dists, _ = dist_matrix.topk(k+1, dim=1, largest=False)  # +1 排除自身
    mean_dists = knn_dists[:, 1:].mean(dim=1)  # (N,)

    global_mean = mean_dists.mean()
    global_std = mean_dists.std()

    mask = mean_dists < (global_mean + threshold * global_std)
    return points[mask]
```

**方案2：体素均值滤波**

将点云体素化后，对每个体素内的点取均值，消除单点扰动的影响。OpenPCDet 的体素化过程天然有类似效果，但可以进一步强化。

### 6.3 方向三：迁移性分析

**代理模型迁移攻击**：用全可微的代理模型（如 PointNet/PointNet++）生成对抗样本，测试这些对抗样本能否迁移到 PointPillars 上（详见 3.5 节）。

**跨检测器迁移**：在 OpenPCDet 中切换到 SECOND 模型（已有配置 `tools/cfgs/kitti_models/second.yaml`），分析对抗样本在不同检测架构间的迁移性。

### 6.4 方向四：有限梯度攻击（可选探索方向）

Robust3DOD 项目展示了通过删除 `@torch.no_grad()` 装饰器启用部分梯度的方案，理论上可实现 PGD 微扰和 Saliency-based 删除。但这违反"不动模型"原则，且梯度仍无法通过体素化回传到输入点云，实际可行性有限。仅作为可选探索方向提及，有兴趣的组员可参考 Robust3DOD 项目。

### 6.5 推荐改进组合

**保中档冲高档的最优路线**：

1. **中档达标**：完成四种梯度无关攻击（Noise+Drop+GeoDrop+Attach）+ 21次评估 + mAP对比表
2. **高档加分1**：从随机攻击升级为几何感知攻击 → 证明"定向攻击比随机攻击更有效"
3. **高档加分2**：实现 SOR 去噪防御 → 证明"简单防御可部分抵御攻击"
4. **高档加分3**：迁移攻击实验 → 分析"3D对抗样本的跨架构迁移性"
5. **高档加分4**：对比攻击在 SOR 前后的效果变化 → 完成攻防闭环

这样最终实验包含：攻击有效性 + 定向攻击改进 + 防御有效性 + 迁移性分析 + 攻防对比，形成一个完整的攻防评估体系。

## 附录 B：攻击算法理论参考

### B.1 CVPR 2019 论文攻击方法概述

CVPR 2019 论文《Generating 3D Adversarial Point Clouds》提出三种白盒攻击方法，均需要梯度反向传播：

1. **坐标微扰（Perturbation）**：使用 C&W 或 PGD 优化，沿损失函数梯度方向微扰点坐标
2. **关键点删除（Dropping）**：基于 Saliency Map 识别关键点并删除
3. **点生成（Generation）**：优化新点位置以最大化攻击效果

**关键限制**：这些方法均针对 PointNet/PointNet++ 分类任务设计，且需要端到端梯度。OpenPCDet/PointPillars 的5个梯度断裂点（见3.2节）使这些方法无法直接使用。

### B.2 Robust3DOD 适配方案（仅供参考）

Robust3DOD 将上述攻击适配到 3D 检测任务，核心修改是删除 `@torch.no_grad()` 装饰器启用 VFE 层梯度。但即使如此，梯度仍无法通过体素化和 spconv 回传到输入点云，实际效果受限。

### B.3 本项目采用的替代策略

| 论文方法 | 需要梯度 | 本项目替代方案 | 无需梯度 |
|---------|---------|--------------|---------|
| PGD 坐标微扰 | 是 | NoiseAttacker（随机高斯微扰） | 否 |
| Saliency-based 删除 | 是 | DropAttacker + GeoDropAttacker（随机/几何感知删除） | 否 |
| 对抗性点生成 | 是 | AttachAttacker + AdvAttachAttacker（随机/密度感知插入） | 否 |
| — | — | 迁移攻击（代理模型白盒 → 目标模型黑盒） | 目标模型无需梯度 |
